_This is the seventeenth installment in a series where we build a toy Next.js on top of Vite. In [Part 15](/15-server-functions), we built server functions. Now we'll add static site generation (SSG) — pre-rendering pages to HTML files at build time, so they can be served from a CDN with no server runtime._

---

## SSG vs. SSR — when to pre-render

SSR renders pages on every request. SSG renders pages once at build time and serves them as static files. The trade-off is freshness vs. performance: SSR always shows current data, SSG serves from a CDN edge with near-zero latency but shows data from build time.

Next.js popularized the hybrid model — some pages are SSG, some are SSR, and ISR (Incremental Static Regeneration) lets SSG pages revalidate on a schedule. We'll implement the first two and sketch how ISR would work.

---

## The `generateStaticParams` convention

For dynamic routes like `/posts/:id`, the framework needs to know _which_ IDs to pre-render. The developer provides this via a typed export:

```tsx title="src/pages/posts/[id].tsx"
import { defineLoader } from "eigen/helpers";
import type { PageProps } from "eigen/types";
import type { RouteParamsMap } from "eigen/route-types";

/**
 * Tell the framework which param combinations to pre-render.
 * The return type is constrained to match this route's params shape.
 */
export async function generateStaticParams(): Promise<Array<RouteParamsMap["/posts/:id"]>> {
  const res = await fetch("https://api.example.com/posts");
  const posts = (await res.json()) as Array<{ id: string }>;
  return posts.map((p) => ({ id: p.id }));
}

export const loader = defineLoader("/posts/:id", async ({ params }) => {
  const res = await fetch(`https://api.example.com/posts/${params.id}`);
  return res.json() as Promise<{ title: string; body: string }>;
});

type LoaderData = Awaited<ReturnType<typeof loader>>;

export default function PostPage({ data }: PageProps<"/posts/:id", LoaderData>) {
  return (
    <article>
      <h1>{data.title}</h1>
      <p>{data.body}</p>
    </article>
  );
}
```

The return type `Array<RouteParamsMap['/posts/:id']>` is `Array<{ id: string }>`. If the route were `/posts/:id/:slug`, it would be `Array<{ id: string; slug: string }>`. TypeScript enforces the constraint — you can't return param objects that don't match the route.

Like `loader` and `middleware`, `generateStaticParams` is server-only: [Part 7](/07-transform-hook)'s transform strips it from the client bundle, so the post-listing `fetch` never ships to the browser.

<TypeDeepDive title="TypeScript: Indexed access types for route constraints">

`RouteParamsMap['/posts/:id']` is an indexed access type — it looks up the key `'/posts/:id'` in the `RouteParamsMap` interface (generated by the plugin from your filesystem routes) and returns the corresponding params type `{ id: string }`. By using `Promise<Array<RouteParamsMap[TPath]>>` as the return type, TypeScript ensures that the param objects you return from `generateStaticParams` match the dynamic segments in the route. If you return `[{ name: 'wrong' }]` for a route with `[id]`, TypeScript reports both the missing `id` and the excess `name` at compile time — no runtime check needed.

</TypeDeepDive>

## Which routes get pre-rendered

The rules:

- **Static routes** (no dynamic segments) are pre-rendered by default.
- **Dynamic routes** are pre-rendered for each param set their `generateStaticParams` returns, and otherwise left to SSR.
- **Routes with their own `middleware`** ([Part 14](/14-framework-middleware)) are skipped unless they opt in. Route middleware usually means auth or per-request logic, and a pre-rendered file is public and identical for everyone.
- **Any route** can opt in or out explicitly:

```typescript title="packages/eigen/types.ts"
export interface StaticGenerationConfig {
  /** Force pre-rendering on (e.g. despite route middleware) or off */
  prerender?: boolean;
  /** Revalidation interval in seconds (see the ISR sketch below) */
  revalidate?: number;
}

export interface RouteDefinition {
  // ...path, component, loader, middleware from Part 14
  generateStaticParams?: () => Promise<Array<Record<string, string>>> | Array<Record<string, string>>;
  staticGeneration?: StaticGenerationConfig;
}
```

```typescript title="src/pages/pricing.tsx"
import type { StaticGenerationConfig } from "eigen/types";

// Fully dynamic pricing — always render per request
export const staticGeneration = { prerender: false } satisfies StaticGenerationConfig;
```

Global middleware still runs during pre-rendering, with a synthetic request that carries no cookies — so pages render the way an anonymous visitor would see them. And once a page is a static file, request-time middleware no longer runs for it. Both are inherent to SSG, and both are reasons to keep personalized routes out of it.

The route plugin exposes the two new exports in its SSR branch, the same way it exposed `middleware`:

```typescript title="plugins/eigen-routes.ts"
...routes.map(
  (r, i) =>
    `  { path: '${r.path}', component: RouteMod${i}.default, loader: RouteMod${i}.loader, ` +
    `middleware: RouteMod${i}.middleware, generateStaticParams: RouteMod${i}.generateStaticParams, ` +
    `staticGeneration: RouteMod${i}.staticGeneration },`,
),
```

The server entry already imports `routes`; it re-exports them so the build step can walk the route table. It also takes over `isBot` from [Part 12](/12-streaming-ssr)'s dev server, so the built server and the deployment adapters in [Part 17](/17-deployment-adapters) can use it without copying it:

```tsx title="src/entry-server.tsx"
export { routes }; // for the SSG build step

// Moved here from server.ts (Part 12)
export const isBot = (request: Request) =>
  /bot|crawler|spider|googlebot/i.test(request.headers.get("user-agent") ?? "");
```

Everything else SSG needs already exists. `renderStream(request, { template, waitForAll })` ([Part 12](/12-streaming-ssr), taking a `Request` since [Part 14](/14-framework-middleware#the-middleware-execution-engine)) runs middleware and loaders, composes the template, and embeds `window.__EIGEN_DATA__` in [Part 13](/13-nested-layouts)'s `RouteData` shape. With `waitForAll: true` it waits for every Suspense boundary and every deferred value before finishing the response — exactly what a static file needs. Pre-rendering, the production server, and every adapter call this one function, so the page markup is assembled in exactly one place.

The template is the client build's `dist/client/index.html`, which already contains the hashed `<script type="module">` and stylesheet tags Vite wrote into it — so a pre-rendered page hydrates exactly like an SSR'd one.

## The SSG build plugin

Pre-rendering needs both builds to be finished: it imports the _built_ server entry to call `renderStream`, and it writes into the client output directory. In [Part 11](/11-framework-plugin), `eigen()` took over build orchestration with a `buildApp` hook marked `order: 'pre'` that builds the client and then the server. A second `buildApp` hook with `order: 'post'` runs after that one has returned — after both builds are complete and on disk:

```typescript title="plugins/eigen-ssg.ts"
import type { Plugin } from "vite";
import { copyFileSync, mkdirSync, readFileSync, rmSync, writeFileSync } from "node:fs";
import { dirname, join, resolve } from "node:path";
import { pathToFileURL } from "node:url";
import type { RouteDefinition } from "../packages/eigen/types";

interface ServerEntry {
  routes: RouteDefinition[];
  renderStream: (request: Request, options: { template: string; waitForAll?: boolean }) => Promise<Response>;
}

/** '/posts/:id' + { id: '1' } → '/posts/1' */
export function pathFromParams(pattern: string, params: Record<string, string>): string {
  return pattern.replace(/:(\w+)/g, (_, key: string) => {
    const value = params[key];
    if (value === undefined) {
      throw new Error(`generateStaticParams for ${pattern} returned no "${key}"`);
    }
    if (value === "." || value === "..") {
      throw new Error(`Refusing to pre-render ${pattern} with ${key}="${value}"`);
    }
    return encodeURIComponent(value);
  });
}

export async function pathsToPrerender(route: RouteDefinition): Promise<string[]> {
  const optIn = route.staticGeneration?.prerender;
  if (optIn === false) return [];
  // Route middleware means per-request logic: never bake it into a public file implicitly
  if (route.middleware?.length && optIn !== true) return [];

  if (route.generateStaticParams) {
    const paramSets = await route.generateStaticParams();
    return paramSets.map((params) => pathFromParams(route.path, params));
  }
  return route.path.includes(":") ? [] : [route.path];
}

export default function eigenSSG(): Plugin {
  return {
    name: "eigen-ssg",
    apply: "build",

    buildApp: {
      // Runs after eigen()'s order:'pre' hook has built client and server.
      // Post hooks run sequentially in plugin order, so deployment
      // adapters listed after eigen() see the pre-rendered output.
      order: "post",
      async handler(builder) {
        const { client, ssr } = builder.environments;
        if (!client.isBuilt) await builder.build(client);
        if (!ssr.isBuilt) await builder.build(ssr);

        const root = builder.config.root;
        const clientDir = resolve(root, client.config.build.outDir);
        const serverDir = resolve(root, ssr.config.build.outDir);

        // 1. Save the template before any pre-rendered page can overwrite it.
        //    From here on, servers and adapters read dist/server/template.html.
        const templatePath = join(serverDir, "template.html");
        copyFileSync(join(clientDir, "index.html"), templatePath);
        const template = readFileSync(templatePath, "utf-8");

        // 2. The raw template must never be served as a page. If '/' is
        //    pre-rendered below, index.html comes back as the real home page.
        rmSync(join(clientDir, "index.html"));

        const server: ServerEntry = await import(pathToFileURL(join(serverDir, "entry-server.js")).href);

        console.log("\n⚡ Pre-rendering static pages...\n");
        const prerendered: string[] = [];

        for (const route of server.routes) {
          for (const path of await pathsToPrerender(route)) {
            // A synthetic request with no cookies: an anonymous visitor
            const response = await server.renderStream(
              new Request(new URL(path, "http://localhost")),
              { template, waitForAll: true }, // a file can't stream: wait for everything
            );

            if (response.status !== 200) {
              // Redirects, 404s from loaders, 500s: leave the path to SSR
              console.warn(`  ⚠ ${path} → ${response.status}, skipped`);
              continue;
            }

            const file = path === "/" ? join(clientDir, "index.html") : join(clientDir, path, "index.html");
            mkdirSync(dirname(file), { recursive: true });
            writeFileSync(file, await response.text());
            prerendered.push(path);
            console.log(`  ✓ ${path}`);
          }
        }

        // 3. Tell servers and adapters which paths are files
        writeFileSync(join(serverDir, "prerendered.json"), JSON.stringify(prerendered, null, 2));
        console.log(`\n  ${prerendered.length} pages pre-rendered.\n`);
      },
    },
  };
}
```

Add `eigenSSG()` to the plugin array returned by `eigen()`, after the main `eigen` plugin.

### Why `buildApp` instead of `generateBundle` or `closeBundle`

- **`generateBundle`** runs _inside_ one environment's build, before its files are written. The server bundle we need to import doesn't exist on disk yet.
- **`closeBundle`** runs after an environment's files are written — but once _per environment build_, so the hook fires after the client build too, before the server exists. Worse, `closeBundle` is a _parallel_ hook: if the SSG plugin and a deployment adapter both use it, Rolldown starts them concurrently, and the adapter can copy `dist/client` while pages are still being written. Plugin order and `enforce: 'post'` don't fix that.
- **`buildApp` with `order: 'post'`** runs once per `vite build`, after the framework's `order: 'pre'` hook has built every environment. Vite awaits each `buildApp` hook in turn, in plugin order — so "SSG, then adapter" is a guarantee rather than a race.

The `isBuilt` checks make the plugin work even without `eigen()`'s orchestration: if nothing has built the environments yet, it builds them itself.

## Hybrid SSR/SSG serving

The production server from [Part 6](/06-production-builds#the-production-server) needs three changes: read the template from `dist/server/template.html`, serve pre-rendered files for the paths listed in `prerendered.json`, and fall back to SSR for everything else.

```typescript title="server.prod.ts"
import { readFileSync } from "node:fs";
import { readFile, stat } from "node:fs/promises";
import { join } from "node:path";
import { H3, serve, serveStatic } from "h3";

const clientDir = "dist/client";
const template = readFileSync("dist/server/template.html", "utf-8");
const prerendered = new Set<string>(JSON.parse(readFileSync("dist/server/prerendered.json", "utf-8")));

// Top-level await: load the pre-built server bundle once at startup
const { renderStream, loadData, callServerFn, isBot } = (await import("./dist/server/entry-server.js")) as {
  renderStream: (request: Request, options: { template: string; waitForAll?: boolean }) => Promise<Response>;
  isBot: (request: Request) => boolean;
  loadData: (request: Request) => Promise<Response>;
  callServerFn: (request: Request) => Promise<Response>;
};

const app = new H3();

// Hashed assets: cache forever, the hash changes when the content does
app.get("/assets/**", (event) => {
  event.res.headers.set("Cache-Control", "public, max-age=31536000, immutable");
  return serveStatic(event, {
    getContents: (id) => readFile(join(clientDir, id)),
    getMeta: async (id) => {
      const stats = await stat(join(clientDir, id)).catch(() => undefined);
      if (stats?.isFile()) return { size: stats.size, mtime: stats.mtimeMs };
    },
  });
});

app.get("/_eigen/data", (event) => loadData(event.req));
app.post("/_eigen/fn/**", (event) => callServerFn(event.req));

app.all("/**", async (event) => {
  const { pathname } = event.url;

  // Pre-rendered page? Serve the file.
  if (event.req.method === "GET" && prerendered.has(pathname)) {
    const file = pathname === "/" ? "index.html" : join(pathname, "index.html");
    return new Response(await readFile(join(clientDir, file), "utf-8"), {
      headers: { "Content-Type": "text/html; charset=utf-8" },
    });
  }

  // Otherwise stream SSR (middleware redirects come back as Responses too)
  return renderStream(event.req, { template, waitForAll: isBot(event.req) });
});

serve(app, { port: 3000 });
```

Checking membership in `prerendered.json` instead of probing the filesystem for `dist/client${path}/index.html` keeps request paths out of filesystem lookups, and makes the set of static pages an explicit build output that adapters can read too.

## Sketch: incremental static regeneration

ISR keeps the speed of a static file while letting it age out. The rule is stale-while-revalidate: serve the existing file immediately, and if it's older than the route's `revalidate` interval, re-render it in the background for the _next_ visitor. On a long-lived Node server, that's a few lines on top of the handler above:

```typescript title="server.prod.ts (sketch)"
import { writeFile } from "node:fs/promises";

const generatedAt = new Map<string, number>(); // path → ms timestamp; seeded at startup
const inFlight = new Set<string>();

function revalidateInBackground(pathname: string, revalidateSeconds: number) {
  const age = Date.now() - (generatedAt.get(pathname) ?? 0);
  if (age < revalidateSeconds * 1000 || inFlight.has(pathname)) return;

  inFlight.add(pathname);
  renderStream(new Request(new URL(pathname, "http://localhost")), { template, waitForAll: true })
    .then(async (response) => {
      if (response.status !== 200) return; // keep serving the old file
      const file = pathname === "/" ? "index.html" : join(pathname, "index.html");
      await writeFile(join(clientDir, file), await response.text());
      generatedAt.set(pathname, Date.now());
    })
    .catch((e) => console.error(`ISR failed for ${pathname}`, e))
    .finally(() => inFlight.delete(pathname));
}
```

The `revalidate` value would come from the route's `staticGeneration.revalidate`, so a real implementation would have SSG record it next to each path (today `prerendered.json` is just a list of paths). The sketch also shows why hosted ISR is a platform feature: serverless functions have no persistent, shared filesystem to rewrite. On a CDN, the same idea is expressed with cache headers such as `Cache-Control: s-maxage=60, stale-while-revalidate` on SSR responses, plus a platform-specific cache purge for on-demand revalidation.

## What to observe

1. **Run `npm run build`** and check `dist/client/` and `dist/server/`. You'll see pre-rendered `index.html` files for each static page, plus `template.html` and `prerendered.json` in the server output.

2. **The pre-rendered HTML is complete** — view source shows server-rendered content, the `__EIGEN_DATA__` script, and Vite's hashed script tags. The page works without JavaScript (for content), and hydrates when JS loads.

3. **Dynamic routes generate multiple files.** If `generateStaticParams` returns 50 posts, you get 50 HTML files under `dist/client/posts/`.

4. **Protected routes stay dynamic.** `/dashboard` has route middleware, so the build log doesn't list it and it has no file. Add `export const staticGeneration = { prerender: true }` and it shows up as `⚠ /dashboard → 302, skipped`: the auth guard redirected the anonymous build-time request.

5. **The type constraint on `generateStaticParams`** — try returning `[{ name: 'wrong' }]` for a route with an `[id]` param. TypeScript catches the mismatch.

## Key insight

SSG is a build-time loop: discover routes, run their middleware and loaders, render to HTML, write files. From Vite's perspective, the interesting hook is `buildApp` — a post-build hook that runs once after all environments are built, in a defined order, giving you access to the built artifacts for post-processing. The framework uses the _server build output_ (the same `renderStream()` used for SSR) to generate the static files, so the entire pipeline — middleware, loaders, layouts — runs the same way whether rendering happens at request time or build time. The only difference is _when_ it runs, and that difference (no cookies, no per-request logic afterwards) is what decides which routes are safe to pre-render.
